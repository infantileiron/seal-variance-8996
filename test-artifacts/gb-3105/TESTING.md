## 需求覆盖映射

**合并计算与逐条相符**
- 30 组随机数据（2–8 组、随机分包）：合并 ANOVA 的 SS/df/MS/F/p/η²/组均值/组标准差与逐条 `anova()` 一致（相对误差 ≤1e-9）。
- API 级对照：同一批 72 条真实样本分别走逐条与汇总模式，两个后台任务结果逐项一致。
- 合并算法为 Chan 并行公式（m2 传递），不展开虚构逐条测量；测试内含朴素 `E[x²]−n·mean²` 公式对照，证明在大偏移下朴素公式灾难性相消而 Chan 保持准确。

**均值接近而方差很小**
- 组均值差 1e-4 量级、组内 sd≈1e-4、每组 40 条分 4 包：合并与逐条一致（≤1e-8），F 有限；合并 ss_within 与 Decimal 高精度参照一致（≤1e-6）。
- 业务量纲（均值≈23.4）合并对照 Decimal 高精度（≤1e-9）；1e8 大偏移压测下合并与逐条 float64 结果同级相符。

**大样本包**
- 3 组 × 3 包 × 100000 条（共 90 万）：合并 n 精确，统计量与逐条一致（≤1e-9）。

**收包规则**
- 同号同内容重试：200 + `deduplicated=true`，台账不重复累计（含 8 线程并发同号，仅 1 个 201、其余 200，落库 1 包）。
- 同号异内容（含跨批次同号）：409 整包拒收，原包内容不变（含 8 线程并发，仅 1 个 201、其余 409）。
- 编号交叠（相邻/包含/同界）：409 整包拒收；8 线程并发交叠争抢仅 1 个 201、7 个 409，落库 1 包（`pg_advisory_xact_lock` 按工艺+批次串行化，包号唯一约束兜底）。
- 校验：n 须等于连续编号范围长度、n≥2、均值 ∈(0,200]、样本标准差 ≥0；只读账号写操作 403。

**缺口核查与缺包不给结论**
- 预期范围登记：重复登记幂等、交叠 409、终点小于起点 422。
- `/summary/gaps`：部分覆盖时报缺口区间（11–30）与状态；收全后 `complete=true`，合并 n/均值/样本标准差与逐条计算一致。
- 缺包（缺口或未登记预期范围）发起汇总分析：后台任务记 failed，错误含“缺包未收全，不给结论”与具体缺口，不产出结论；汇总模式拒绝 `lot=全部`（422）。

**并发收包与发起分析**
- 汇总快照在独立 REPEATABLE READ 事务中读取：数据库级验证快照事务看不到其首次读取之后提交的包，各组依据同一已收全状态。
- 5 轮并发（收包线程与发起分析线程竞争）：任务或 failed（缺包）或 completed 且结果 n 等于其快照包合计，无中间撕裂态。
- 发起后新包不改变该次结果：任务完成后追加计划外包，原任务结果 n 与 checksum 不变；新任务才纳入追加包（n=88）。

**保留原逐条分析**
- 逐条模式（含 `lot=全部` 跨批次）回归通过；样本不足仍记 failed；seed 的逐条复核任务结果与改动前一致。

## 复跑说明

测试数据以时间戳为批次/包号前缀，可重复执行不冲突；seed 幂等（连跑两次计数不变）。worker 中断恢复（running→queued 重算）已验证，重算结果与原值一致。
